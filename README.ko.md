# FaceValue · 정가

[English](README.md) · **한국어**

**Midnight 위의 암표 방지 티켓. 모든 팬은 인증되지만, 누가 누구인지는 아무도 모릅니다.**

2026년 8월 28일 개정 공연법의 암표 규제가 시행되었습니다. 이제 티켓 판매 플랫폼은 구매자를 확인해야 하고, 정가를 넘는
재판매는 불법입니다. 그런데 지금까지 업계의 해법은 모두 더 많은 개인정보를 수집하는 방식입니다. 입장 시 실명 신분증 확인,
하이브의 얼굴 인식 입장 *Face Pass*, 홍채 스캔 등이 그렇습니다. 동시에 개정 개인정보 보호법(2026년 9월 11일 시행)과
쿠팡의 사상 최대 과징금(약 6,247억 원) 이후, 그런 데이터를 보유하는 것 자체가 위험이 되었습니다.

FaceValue는 **아무것도 수집하지 않고** 인증합니다.

| 단계 | 일어나는 일 | 누가 무엇을 아는가 |
|---|---|---|
| **최초 1회 등록** | 발급자가 팬이 유일한 사람인지 확인하고, Midnight의 머클 레지스트리에 *해시 커밋먼트*만 추가합니다. | 발급자는 "새로운 사람 1명"만 압니다. 체인에는 해시만 남습니다. |
| **추첨 응모** | 팬은 레지스트리의 *어떤* 구성원임을 영지식으로 증명합니다. 공연당 1회만 가능합니다. 속도 경쟁이 없으므로 매크로가 무의미합니다. | 응모 수는 공개되지만, 누가 응모했는지는 알 수 없습니다. |
| **공정한 추첨** | 주최자는 응모 시작 전에 시드를 봉인합니다. 시드와 모든 응모자의 난수, 공개 비콘을 합쳐 좌석 수만큼의 당첨 구간을 정합니다. | 누구나 추첨을 재검증할 수 있고, 응모를 본 뒤 시드를 바꿀 수 없습니다. 비콘 값은 주최자가 공개 시 게시하며, 컨트랙트가 아니라 오프체인에서 drand와 대조합니다(한계 참고). 주최자가 공개하지 않으면 마감 후 누구나 추첨을 실행할 수 있고, 공연은 *주최자 불이행*으로 표시됩니다. |
| **정가 구매** | 당첨자는 **실드(shielded)** tKRW로 정확히 정가를 결제합니다. 1인당 한도는 nullifier로 강제됩니다. | 결제자의 지갑과 잔액은 숨겨집니다. |
| **반납 = 유일한 출구** | **양도 기능은 없습니다.** 티켓은 정가 환불로 풀에 반납하는 것만 가능하고, 다음 인증 팬이 정가에 구매합니다. | 정가를 넘는 가격은 컨트랙트를 통과할 수 없습니다. 비밀값을 넘긴 판매자는 구매자가 체크인하기 전까지 티켓을 회수할 수 있습니다(한계 참고). |
| **집에서 체크인, 입구에서 바로 입장** | 체크인하면 티켓이 체인에서 사용 처리되고 새 기기 키가 등록됩니다. 입구에서는 30초마다 재서명되는 QR을 보여주고, 게이트는 오프라인으로 수 밀리초 만에 서명을 확인합니다. | 공연장은 "유효함, 아직 입장 안 함"만 압니다. 이름도, 신분증도, 얼굴도 필요 없습니다. |

## 실제 동작 vs. 예시

| 구성 요소 | 상태 |
|---|---|
| Compact 컨트랙트 (`contract/src/facevalue.compact`, 서킷 10개) | **동작.** 실제 증명 키로 컴파일됨 |
| 실제 ZK 증명으로 전체 생애주기 실행 | **Local Devnet에서 동작**, 트랜잭션 18건 (`docs/evidence/local-run.json`). `npm run localnet && npm run e2e -- local`로 재현. Preprod 실행 스크립트(`.github/workflows/preprod.yml`)는 있으나 faucet 지급이 작업 시간 내에 도착하지 않았습니다 |
| 컨트랙트로의 실드 결제와 환불 | **Local Devnet에서 동작**, 실제 증명 (`cli/src/spike-pay.ts`) |
| 공격 스크립트 (재판매 회수, 봇, 중복 응모, 시드 교체, 정가 초과 결제, 중복 체크인) | **동작.** `npm run attack`. 알려진 빈틈은 `contract/src/test/limits.test.ts` 테스트로 고정 |
| 공개 상태를 읽는 공연 대시보드, 한/영 전환 | **구현됨.** Preprod 배포가 게시되면 Midnight 인덱서에서 직접 읽습니다. 그 전까지 홈페이지는 기록된 Local Devnet 실행을 그렇게 표시해 보여줍니다 |
| 기기에 묶인 회전 입장 패스와 오프라인 게이트 스캐너 | **동작** (WebCrypto P-256, 추출 불가 키) |
| 신원 발급자 | **데모 발급자 키.** 실제 여권 확인(Self, *proof of human*) 연동 예정 |
| tKRW | **테스트 토큰.** 누구나 발행할 수 있는 테스트넷 실드 스테이블코인 |

### 알려진 한계

- **환불 주소**: 환불이나 주최자 출금 시 *받는 지갑의* 실드 주소가 체인에 드러납니다. 신원이나 어떤 티켓인지는 드러나지 않습니다. 환불마다 새 지갑 주소를 쓰는 것을 권장합니다.
- **비밀값을 넘기는 재판매**: 판매자가 팬 비밀값을 넘기면, 구매자가 체크인하기 전까지만 티켓을 회수할 수 있습니다. 구매자가 먼저 체크인하면 티켓이 구매자 기기에 묶이므로, "체크인 후 결제" 방식의 거래는 여전히 가능합니다. 판매자는 팬 자격 전체도 넘기게 됩니다. 개선 예정: 공연 직전에만 체크인 허용.
- **비콘 신뢰**: 주최자가 공개 시 drand 비콘 값을 게시합니다. 컨트랙트는 봉인된 시드는 검증하지만, 비콘이 공지된 drand 라운드와 일치하는지는 검증하지 않으므로 감사자는 drand와 직접 대조해야 합니다. 기록된 Local Devnet 실행은 고정 테스트 값을 사용했습니다. 주최자가 불이행하면 응모자 난수만으로 추첨하며, 마지막 응모자가 영향을 줄 수 있습니다. 이런 공연은 *주최자 불이행*으로 공개 표시됩니다.
- **단계는 주최자가 진행**: 당첨자 구매 기간 종료와 공연 종료 시점을 주최자가 정합니다. 일찍 종료하면 이후 체크인과 환불이 막힙니다. 개선 예정: 컨트랙트가 최소 기간을 강제.
- **입장 코드**: 코드는 자신의 30초 구간과 앞뒤 한 구간까지 인정되므로, 스크린샷은 찍은 지 30~60초 후 무효가 됩니다. 오프라인 스캐너는 각자 입장 목록을 가지므로, 게이트가 여러 곳이면 입장 전에 동기화해야 합니다.
- **동시성**: 모든 구매가 하나의 트레저리 코인을 갱신하므로, 같은 블록의 구매는 충돌하고 재시도됩니다.

## 실행

```bash
npm install
npm test                 # 테스트 27개: 컨트랙트 시뮬레이터, 입장 패스 암호, 알려진 한계
npm run attack           # 컴파일된 서킷을 대상으로 한 공격 스크립트
npm run localnet         # 로컬 Midnight 노드, 인덱서, 증명 서버 (Docker)
npm run e2e -- local     # 실제 증명으로 전체 생애주기 실행
npm run dev -w app       # 웹 앱: 대시보드, 팬, 입장 패스, 게이트 스캐너
```

## Midnight 활용 방식

- **Compact가 증명하는 것**: 레지스트리 소속(비공개 머클 경로), 공연당 1인 1응모, 당첨 여부(시드 커밋먼트와 정수 추첨, 나눗셈은 서킷에서 검증), 1인 한도(슬롯 nullifier, 슬롯 번호는 비공개), 미사용 티켓 소유(머클 경로 + nullifier), 정확한 정가 결제.
- **공개하는 것**: 각종 수량, 공개 후의 추첨 시드, nullifier와 커밋먼트, 가격.
- **실드 토큰**: 컨트랙트 트레저리로의 결제(`receiveShielded`, `mergeCoinImmediate`), `sendShielded`로 환불.
- **왜 프라이버시가 필요한가**: 법은 신원에 묶인 티켓을 요구합니다. 영지식이 없다면 신원에 묶인 티켓은 곧 "누가 어떤 공연에 갔는지"의 데이터베이스가 됩니다.
